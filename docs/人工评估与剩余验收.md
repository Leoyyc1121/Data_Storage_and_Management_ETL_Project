## 人工填写方法

每对保持 `pair_id`、`partition`、左右证据与包头 `evaluation_binding` 不变，只填写：

| 字段 | 要求 |
| --- | --- |
| label | 电影为 same_work / different_work；人物为 same_person / different_person；证据不足为 unresolved |
| labeler_type | 只有真人独立判断才填写 human |
| labeled_by | 真实标注者，不虚构姓名或第二名成员 |
| labeled_at | 实际时间及明确时区，例如 +08:00 |
| labeling_evidence | 能复核的原件、哈希、定位和作品/人物信用上下文 |
| rationale | 身份、版本、冲突及裁定理由，不能仅写“标题/姓名相同” |

电影检查同名、续集、翻拍、合集、剪辑、时长及分集/完整长片；人物检查完整姓名、首字母、同名不同人、作品信用、角色及时期。证据不足不猜测；unresolved 不计入至少 100 对已裁定标签。

推荐两人独立判断并填写 `reviews` 数组。分歧时保留双方原判断，由真实人工在 `adjudication` 中裁定；无裁定的分歧会被拒绝。单人可登记，但须如实说明没有双人一致性验证。程序核验声明和结构，不能证明背后确由真人完成。

## 评估命令

```powershell
& .\.venv\Scripts\python.exe -m json.tool data/evaluation/annotation_v2/movies.labels.json > $null
& .\.venv\Scripts\python.exe -m json.tool data/evaluation/annotation_v2/people.labels.json > $null
& .\.venv\Scripts\python.exe src/quality/evaluate_task4.py --labels data/evaluation/annotation_v2/movies.labels.json
& .\.venv\Scripts\python.exe src/quality/evaluate_people.py --labels data/evaluation/annotation_v2/people.labels.json
```

两类各需至少 100 对真正已裁定标签，同时包含应合并与应分离两类及困难案例。120 对中若超过 20 对无法裁定，数量仍不足；先交接缺证对，不更换登记队列凑数。全部对（包括 unresolved）必须来自绑定保留集，模型变化后不能继续沿用旧绑定。

空标签包按设计报错，不产生假指标。通过后分别生成 `reports/task4/evaluation_results.json` 与 `reports/task5/evaluation_results.json`：TP/FP/FN/TN、Precision/Recall/F1、错误对、覆盖率和争议数。零分母为 NULL；样本指标不是全量准确率。含来源正文的包不公开上传 Git。
