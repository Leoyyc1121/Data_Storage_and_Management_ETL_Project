# 项目交付与本地恢复

## 提交边界

按指导文档第11节，提交正式报告、完整实现、ETL作业和配置、模型与SQL、依赖版本、全量统计、采集及合并/血缘证据、评估材料登记、离线验收与复现说明。大文件可以提供校验和、存储位置和恢复方法，来源内容的分享还必须符合使用条件。

本项目提交范围为根目录README、统一实施记录、requirements.txt、Git忽略规则，以及config、src、tests、docs、sql、reports中的当前实现与必要证据。`reports/final/submission_manifest.json`列出具体文件及SHA-256；清单不自包含其自身哈希，校验报告也不纳入递归哈希。历史记录中的旧路径依照清理清单定位，不代表当前运行仍依赖旧目录。

不上传原始或派生数据库、Parquet、第三方原件、含来源正文的标注/验收包、虚拟环境、密钥、指导Word及旧报告草稿。保留完整实现和原件恢复方法，不以零标签的标注包或一个小样本冒充完整成果。

## 最终校验

```powershell
& .\.venv\Scripts\python.exe -m pip check
& .\.venv\Scripts\python.exe -m unittest discover -s tests/unit
& .\.venv\Scripts\python.exe src/quality/verify_submission.py
& .\.venv\Scripts\python.exe src/quality/audit_requirements.py --strict
```

提交检查核对文件边界、JSON、本地文档链接、常见凭据模式以及必要本地成果的存在和登记大小。大型历史哈希与本次重新计算的哈希分开标注，不把“文件存在”称为内容全量重放。严格要求审计因人工标签及额外合并组仍缺失，当前应返回非零，不能为追求退出0而删除检查项。

克隆Git仓库后先按README恢复允许使用的原件、安装固定依赖，再按DAG重建。已有本地数据时可运行fixed_v2离线验收；如需在其他机器演示，须在许可范围内另行传递对应固定包，公开仓库不自动附带该受限材料。
