## 标注与目标结果的对照

实际对照固定 final_v8 目标：电影71对确定来源判断中，64对没有双方各一个 `single_work` 映射，列为模型未映射/范围不适用；可比较7对均为不同作品。该子集没有正类预测与正类参考，Precision、Recall、F1 均为 NULL，不能称为电影匹配满分。

人物116对确定参考均可对照目标，得到 TP57、FP0、FN2、TN57；来源参考一致性 Precision 1.0、Recall 0.9661、F1 0.9828。涉及9个临时身份侧，且参考与系统共享来源人物号和原始信用，存在来源重叠及重复原件，故这些数值仅用于诊断，不是独立人工准确率，也不能外推全量。

逐对比较明细保留在本机 `data/evaluation/source_annotations_v1/model_comparison.details.json`，不公开发布来源衍生逐对记录。独立人工准确率仍为空。

## 检查与重建

在项目根目录运行：

```powershell
& .\.venv\Scripts\python.exe -m pip check
& .\.venv\Scripts\python.exe -B -m unittest discover -s tests/unit
& .\.venv\Scripts\python.exe -B src/quality/finalize_annotations.py verify
& .\.venv\Scripts\python.exe -B src/quality/finalize_annotations.py compare
& .\.venv\Scripts\python.exe -B src/quality/verify_submission.py
```

标注检查核对来源原件523个记录引用的 SHA、输入绑定、编号覆盖、每对理由与证据引用、最终文件哈希以及人工字段不存在。检查通过证明的是结构、字节完整性和可追溯性，不证明所有来源事实都正确。

重建标注时恢复本机 `review_draft_v1` 的输入成果，执行 `finalize_annotations.py build --directory data/evaluation/source_annotations_v2` 等新目录，禁止覆盖已有版本。正式 ETL 全量重建、固定原件离线重建、中断恢复、隔离重建及十条查询，分别按 README 和[交付与恢复](交付与恢复.md)执行。大文件不能只凭 Git 克隆恢复。

## 封装交付包

```powershell
& .\.venv\Scripts\python.exe -B src/quality/package_delivery.py --output 'D:\My projects\ETL_Project_Final_20261019.zip'
```

输出路径必须在项目外、文件不存在；重复打包换用新文件名。程序先检查本轮范围验收，再更新提交清单，封装完整清单及两个自身排除文件，实际执行 ZIP CRC 和每个成员 SHA 核对。ZIP 旁的 `.receipt.json` 登记实际大小、文件数、哈希与封存时刻，避免自包含哈希循环。

交付包包含代码、配置、报告、SQL、测试、小型统计和必要工程证据。原始评论、35 GB 数据库、第三方原件及派生逐对标注因体积和使用条件留在本机，不纳入公开代码包；提供位置、哈希与恢复方法。标注 JSON 可在上述本机路径直接查看，不需要名字或时间才能使用。

本轮范围检查可以通过，原课程 `audit_requirements.py --strict` 仍可能按设计退出1：独立人工标签、历史压缩原件/准确下载时刻及同名案例适用范围并未因用户调整交付范围而变成已满足。HTML成功0、上映完整日期0、总体作品识别率低等已有事实和覆盖限制继续保留，不用打包状态代替数据质量结论。
