# 人工评估与剩余验收

## 当前结论

工程流程可运行不等于所有课程验收已完成。目前实际跨版本合并仍为 3 组，电影和人物独立人工标签均为 0，Precision、Recall、F1 仍为 NULL。本文件说明补齐证据的操作流程，不将 AI 判断、外部 ID 相同或合成测试称为人工评估。

## 已准备的标注包

```powershell
& .\.venv\Scripts\python.exe src/quality/prepare_human_evaluation.py
```

本机输出为 `data/evaluation/annotation_v1/movies.labels.json` 和 `people.labels.json`，各 120 对。重复执行不会覆盖已经修改的人工标签；如确需另建版本，使用 `--output-dir` 指向新目录。原始保留队列、来源哈希和模型指纹不修改，交接登记见 `reports/final/human_evaluation_handoff.json`。

请使用这些盲化标注包，不直接用人物原保留队列标注。原队列含模型绑定的外部人物 ID、身份状态和生卒年；这些字段现已从标注包中移除，按模型组成的候选分层也不向标注者展示，避免把模型答案当金标准。保留原始姓名、角色、作品上下文、来源记录和断言定位，供独立核查。电影包也不展示分类模型的结论。

电影候选来自单独保留的同名、近似标题与易混淆候选；开发对已排除。人物原保留集为 60 对跨作品候选、30 对相似姓名和 30 对首字母候选，排除 265 条开发来源及 5 个别名案例人物。这些候选类别不是人工正负标签，也不保证现有材料足以裁定 100 对。若证据不足，标为 unresolved；不得为了凑数猜测或在查看模型结果后反向填写标签。

## 人工如何填写

每对保留 `pair_id`、`partition`、左右证据和包头 `evaluation_binding` 不变。可直接填写下列六个字段：

| 字段 | 填写规则 |
| --- | --- |
| label | 电影为 same_work / different_work；人物为 same_person / different_person；无法裁定为 unresolved |
| labeler_type | 只有真实人工标注才填写 human |
| labeled_by | 实际标注者身份，不填写 AI 或虚构人员 |
| labeled_at | 实际标注时间，包含时区，例如 ISO 8601 的 +08:00 |
| labeling_evidence | 能复核的原件定位、哈希、信用上下文或合法外部证据；仅“名字相同”不足以合并 |
| rationale | 解释作品/人物身份、版本例外、冲突及裁定依据 |

电影需特别检查同名作品、翻拍、续集、合集、不同剪辑和时长；人物需检查全名、首字母、同名人物、作品信用、角色和时期。不能把标题或姓名相似单独作为身份依据。人工可以保留未解决状态，但 unresolved 不计入至少 100 对已裁定标签。

推荐两人独立查看同一原件，填写每对的 `reviews` 数组；数组中的每个判断均含上述六个字段。两人身份不得相同。若判断不一致，保留原判断，由实际人工在 `adjudication` 中填写同样的六个字段并解释争议处理。没有裁定记录的分歧会被评估器拒绝。单人标注仍可登记，但报告须说明未做双人一致性验证，不能虚构第二名标注者。

## 标签齐全后评估

```powershell
& .\.venv\Scripts\python.exe src/quality/evaluate_task4.py --labels data/evaluation/annotation_v1/movies.labels.json
& .\.venv\Scripts\python.exe src/quality/evaluate_people.py --labels data/evaluation/annotation_v1/people.labels.json
```

两套评估器都要求至少 100 对真实、可追溯的已裁定标签，并同时包含应该合并和不应该合并的两类。未填写的包按设计报错，不产生假准确率。包内所有对（含 unresolved）均必须属于登记的保留集；不允许改队列、换模型后继续沿用旧标签绑定。

输出保留 TP、FP、FN、TN、Precision、Recall、F1 和误合并/漏合并对的 ID。另列人工处理覆盖率、已裁定覆盖率、人工 unresolved 比率与分歧裁定数；人物的模型待确认率单列，不与人工未解决率混淆。零分母按 NULL 处理，不算满分。这些是构造样本的指标，不是全量准确率；程序验证的只是人工作业声明及结构，不能证明声明确由真人完成。

## 还需要合法证据的项目

- 任务 4：至少两个额外、经完整簇一致性检查的真实跨版本合并组。现有单个待应用提案不算新增合并，更不能把一个作品拆成多个案例凑数。
- 任务 4/5：各至少 100 对独立人工裁定，包含两类及困难案例；标注前与开发材料隔离。
- 任务 5：最终目标上下文中更充分的同名不同人证据。候选目录中的同名例不冒充全部已加载人物。
- 任务 1：最初压缩文件及其校验、准确下载时刻的缺失历史证据。如原件未保留，应保持未知，重新下载的时间不能冒充首次下载。
- 任务 2：VPN 开启与关闭后的 robots 预检均为 503；访问受限证据与替代来源覆盖保留。只有取得允许使用的真实页面/快照，才能新增 HTML 成功、适配后续 HTML 输入并以新版本重算。

这些缺口继续在最终要求审计和报告中列明。补齐真实证据后重跑评估和审计，不只修改 README 中的完成状态。
